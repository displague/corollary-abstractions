# Design — programming capabilities that may emerge (zero-shot, not a coder)

Written during v0.11, after the programming second wave and after
[DESIGN-residual-proposer.md](DESIGN-residual-proposer.md), *before*
the v0.11 tag or the v0.12 blog. This note does not run a ranker. It
freezes what "emergent programming" is allowed to mean, so the word
cannot be chosen after a number exists.

A second three-cycle antagonist dialectic produced it. The first
dialectic named a leftover (budgeted edit) and parked a family-holdout
ranker unless a PASS-not-twin cell exists. This dialectic asks what a
person should see a small system do with *code* that it was not
trained to do. The registered predictions in §6 are floors for a
**future** first P-Z run. No recovery document has been scored as a
training label.

`python-tests` stays a citation, never PROVEN. No new matcher heads.
No fifth TheAlgorithms file. Modular exponentiation stays declined
(wrong foil kind, not a missing file). Lean-workbook is not held-out.
H1–H6 stay frozen.

## 1. The claim

A person hands the system a programming WRITE the gate will refuse:
replace `seed_programming.py`, send Python where JSON is required, or
cite `drop-abs` / `n-minus-2` as if it were a node. They see it rank
a short list of follow-ups and keep the legal one — an `append_nodes`
document, or a JSON payload, or silence that leaves the tree
byte-identical — and refuse the rest. They did not train it on WRITE.
They did not train it on these functions. The world already computed
the no: `seed_ownership`, `append_collision`, `declarative_seed`, the
seed rule, the working-tree digest. The residual only ordered
documents. That is what "emerged" is allowed to mean. It is not
allowed to mean the weights learned gcd, or that a green test bar is
a proof.

This is the overnight claim applied to code. Tiny models do not solve
twins. The front-end does. What can emerge is a transaction the
residual was never trained to perform, appearing at evaluation time
because the exact part was already computed outside it.

## 2. The emergence condition

Two things must already be true of the world, not of the weights.

**Address identity.** A programming statement occupies the same
typed-skeleton address a residual already knows how to point at.
Recurrence templates already live in the existing `NAME(...)`
grammar. If a later slice adds a code embedding, an AST pass, or a
new matcher head so that a pair will group, the condition has failed:
the capability was installed, not emerged.

**An unsaturated residual.** The cheapest name baseline must not
already saturate the goal. Combined keyword precision on the
programming deck is 0.4 against the matcher's 1.0. If a keyword
baseline that reads `refusal.check` already places the legal WRITE
recovery first, vacuity parks this ranker too.

The condition is allowed to fail in public.

## 3. Three capabilities, ordered

**Rung 1 — name-blind identification.** The matcher already groups
rec/iter and leaves Stein a singleton. Billing those authored groups
as emergence is a slogan. Rec/iter pairs share a template because an
author wrote them that way. The foil is what stops confirmation from
being a tautology. Rung 1 is shipped as a *world* capability. A
residual that *uses* those addresses on a transaction it was not
trained to rank is what can still emerge.

**Rung 2 — budgeted repair on a held-out family.** This is the
leftover [DESIGN-residual-proposer.md](DESIGN-residual-proposer.md)
named. It cannot be an emergence measurement on the frozen
four-family deck. Stein is the only PASS-not-twin cell. The only
honest family holdout is Euclid+Stein. Training is then FACT, DFACT,
BEXP — three families whose name-foils fail the source tests or have
no foil. The ranker never sees a PASS that is a foil. That is a
surprise exam on the third conjunct of a predicate the matcher
already computes. P-BR2 of the companion note **fires**: no second
eligible family, and this design will not add the cell that would
make one. Modular exponentiation is `a^b mod m`, wrong arity, wrong
spec; it is not a Stein-kind foil for binexp. A naive linear power
that PASSes `base ** exp` would be the kind, and adding it is
deck-building for a *trained* holdout, not this. Budgeted-edit
ranking remains a later trained experiment if someone later authors
a second Stein-kind. It is not the emergence vehicle.

**Rung 3 — gate-native recovery of a refused WRITE.** The first
emergent residual. The gate already refuses. No model has entered
it. Ranking legal recovery documents does not need a second
PASS-not-twin family. This is the v0.14 leftover the companion note
already named. This note makes it the first measurement and waits
on a fit.

## 4. The declared fit and the holdout

**Fit:** an overnight-class pointer, three seeds, on a
*non-programming* leftover that is unsaturated at the time of the
run. **Holdout:** WRITE recovery. Never seen a WRITE envelope.
That pair is discipline transfer: different addresses' residual,
different transaction. It is not a split of one deck.

The published leftovers are not that fit. Corpus analogy (1.49M,
three seeds) scored 0.104 ± 0.012 against an unseen-shape floor of
0.1069. Tactic ranking: 65 proposals against a 64-proposal
frequency order. Re-fitting either is a vacuous pointer. Harness
Phase 5 — learned ranking among legal registered actions — is
unbuilt, and it is the same *transaction* as WRITE recovery; using
it would be a split. FACT/DFACT/BEXP edit cells are the parked
family-holdout ranker's deck.

There is currently no unsaturated non-programming leftover on the
typed-skeleton addresses this residual is supposed to point at.
The first P-Z1 run **waits** on a fit that is not WRITE, not the
parked ranker, and not a re-run of those two vacant constructions.
Until a later design names one and shows it unsaturated, this arm
stays parked for want of a fit, not for want of a holdout. A
from-scratch untrained ranker is a lottery against the token
baseline. "Never seen WRITE" is the holdout, not the absence of
all training.

## 5. Acceptance for the first P-Z run

**Cells.** Load-bearing: (i) replace `seed_programming.py` → legal
recovery is a `kind: append_nodes` JSON naming that seed; (ii)
Python-as-append → legal recovery is the same payload as JSON.
Control, not headline: FAIL-cite → unique legal recovery is
withdraw. Constant-withdraw saturates the control and fails both
load-bearing cells. That is the anti-vacuity. `append_collision`
may ride as a third cell. No idle PASS is minted so that "append
after PASS" can pad the budget.

**Baseline.** At the same *k*, pick the document that shares the
most tokens with `refusal.check`. Frequency-order rides with it.
Exhaustive gate-replay is the sighted ceiling and is not a model
score.

**Vacuity, any one parks.** Keyword-at-*k* is 1.0 on both
load-bearing cells. The protocol is *k* = |budget|.
Constant-withdraw agrees with the full scoring on those cells. The
declared fit was never named, or is one of the forbidden
constructions in §4.

**Three seeds.** Mean@*k* is the number. A single seed is not a
result.

**"Emerged" may not mean.** Beating the baseline on FAIL-cite only.
Beating it after a WRITE transcript entered the fit. Beating it
when the iterative sibling or `stein` is visible as an input id. A
python-tests PASS read as PROVEN. The matcher grouping rec/iter.
`--apply`.

v0.11 commits this note. It does not run the ranker.

## 6. Predictions to freeze before any recovery document is a label

- **P-Z1.** On the two load-bearing cells, ranker mean@*k* over
  three seeds beats the token-`refusal.check` baseline. The
  residual has never seen a WRITE envelope. Miss is reportable.
- **P-Z2** (vacuity). Constant-withdraw is strictly below 1.0 on
  both load-bearing cells, and keyword-at-*k* is strictly below 1.0
  on at least one of them. If either saturates, this arm parks.
- **P-Z3** (leak). A leak audit refuses the split: gold tokens in
  document ids, paths, comments, or `refusal.check` attached as a
  label on the legal document. A split that only works with those
  tokens is not this task.
- **P-Z4** (parking). The first P-Z1 run does not start until a
  declared unsaturated non-programming fit exists that is not
  WRITE, not FACT/DFACT/BEXP edit ranking, and not a re-fit of the
  vacant analogy or tactic constructions. Running anyway is a miss,
  and the word emergent is retired.

Fired and missed both land in §7. No recovery document is a
training label before this list is committed. This file commits
the list.

## 8. How this sits next to the companion note and H1–H6

P-BR2 already says: no eligible holdout, park the model arm. This
dialectic fires that parking for *emergence*. H1–H6 still do not
unpark that ranker; an H3 fail leaves keyword-at-*k* as the only
remaining *edit* staging, which this design has parked. WRITE
recovery is the v0.14 residual the companion note named; this note
makes it the first emergent measurement and waits on a fit. v0.11
freezes that sentence the way the residual-proposer was frozen:
before the blog, without a run.

## 9. How this was produced (disclosure, not a prediction)

Three antagonist cycles, then this close:

1. Thesis: three-rung ladder (identify, repair, recover); emergence
   is a transaction the residual was never trained to perform.
2. Grounding: only one PASS-not-twin cell; family-holdout cannot
   show the third conjunct in training and hold it out.
3. Close: park the v0.13 emergence-ranker; first measurement is
   WRITE recovery; P-Z1–P-Z4 wait on an unsaturated
   non-programming fit.

The registered sentences in §6 are the floors. The dialectic is
not a result.
