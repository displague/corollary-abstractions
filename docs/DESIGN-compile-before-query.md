# Compile the space before asking the question

Status: **chosen forward direction; no builder, closure, adapter, or result
exists.**  v0.14's already-registered clarification experiment remains the
current cycle.  This is the architectural direction that follows it unless a
construction gate below refuses the idea.

## 1. The larger move

The project can answer a question by running a bounded search.  It cannot yet
build a reusable account of *everything reachable within a small bound* and
then answer questions that were not known when that account was built.  In
particular, failure to find a path is not evidence that no path exists.

The next boundary is to compile a complete small possibility space **before a
goal is supplied**.  Once checked, that one object can answer two kinds of
question exactly:

- this endpoint is reachable, with a shortest replayable sequence; or
- this endpoint is not reachable within the declared bound, because every
  legal move from every interior state was accounted for.

This changes the project from a collection of question-specific runs into an
instrument that can support later questions.  The word *within* is
load-bearing.  Nothing here proves an unrestricted negative, predicts the
world, or turns fictional rules into facts.

The first implementation contains no learned component.  If ordinary
breadth-first enumeration closes the space, there is no graded residue to
learn.  If it cannot close the space under the registered ceiling, a learned
ordering may not rescue the claim.

## 2. Why this direction, and what it refuses

Three independent, project-blind thought experiments were challenged twice
with this repository's actual constraints.

1. **Check whether exact operations agree when composed.**  The strong
   remainder was to retain two replayable routes to the same result and expose
   their first disagreement.  This becomes an integrity property of the
   compiled space, not a new similarity link.
2. **Make a person's earlier forecast temporarily unavailable while asking
   what they remember forecasting.**  That is a real experiment in hindsight
   reconstruction, but it does not extend this project's central machinery.
   It is declined.  Its useful lesson survives only as ordering discipline:
   seal the possibility space before selecting a persuasive target.
3. **Let people state new bounded questions over existing exact worlds.**  The
   first proposal was another goal-first controller.  Under pressure it became
   the direction here: compile a goal-free closure, check it independently,
   and query it later.

For one implementation cycle this direction suspends three familiar proxies
for progress:

- adding more statement records;
- counting more pairwise matches;
- attaching a learned comparison to every new capability.

More connections do not establish that operations compose.  A model arm does
not improve an exact exhaustive construction.  The project should first find
out whether its existing exact worlds can support a common checked calculus.

## 3. The new object

The first-class object is a `BoundedClosure`:

```text
BoundedClosure {
  format_version
  source_manifest
  adapter_id + adapter_digest
  action_schema + action_schema_digest
  horizon
  initial_state
  states[] {
    state_digest
    canonical_state
    minimum_depth
    outgoing[] {
      canonical_action
      disposition = illegal | successor
      successor_digest | refusal_code
    }
  }
  closure_digest
}
```

For every state below the horizon, `outgoing` contains **every syntactically
possible action** generated by the frozen finite action schema.  It records
either the native verifier's refusal or the exact successor.  States at the
horizon are boundary states; they are not called exhausted and make no claim
about the next step.

The object is generated.  Nobody edits it by hand.  Its source is the same
kind of author-owned, reproducible declaration as the repository's corpus
seeds.

The closure is goal-free.  It contains no desired endpoint, success predicate,
reward, query text, or model score.  A later query supplies one exact canonical
target state and asks whether its bytes **and** digest occur.  A digest match
with unequal canonical bytes is refused as corruption.  Presence returns a
shortest native action sequence.  Absence returns
`NOT_REACHABLE_WITHIN_HORIZON`, never plain `impossible`.

## 4. What a world must register

A world is eligible only if it can expose four deterministic operations:

```text
initial_state(frozen_sources) -> native_state
action_schema(frozen_sources) -> finite typed parameter domains
validate_and_apply(native_state, canonical_action) -> refusal | native_state
canonicalize(native_state) -> canonical bytes
```

The action schema is data, not a callback.  It declares a finite product of
action names and typed parameter values.  The generic checker enumerates that
product itself; it does not trust the builder or a search adapter to reveal
which actions exist.

This registration does not make a native verifier correct.  It makes the
verifier's own operational world finite, replayable, and auditable.  The
closure certifies what that versioned code permits within the bound—not
mathematical truth, physical realism, narrative quality, or completeness of
the authored rules.

The first slice must register **two existing worlds** through one interface.
The intended candidates are the committed story state and deterministic
diagram state because both already have canonical data and exact checks.  That
is a hypothesis, not a fact granted by this design.  The story actions are
currently shaped around one recorded run, while diagram mutations are not yet
a transition adapter.  If two worlds cannot expose finite schemas without
world-specific branches in the builder or checker, the construction gate
misses and the design parks.  Do not invent a third toy world to make it pass.

## 5. Independent checking

The builder is untrusted.  The closure file is untrusted.  The existing
controller, policies, search code, and any future model are untrusted.

The generic checker builds the expected reachable graph independently rather
than checking only that the closure's claims are internally consistent.  It:

1. reloads and digest-checks every frozen source;
2. regenerates the initial native state;
3. enumerates the complete action product from the declared schema;
4. sends each native-format action directly to the world's existing verifier;
5. canonicalizes every accepted successor itself;
6. performs its own canonical breadth-first traversal from the regenerated
   initial state;
7. requires exact bidirectional equality between that derived graph and the
   closure: the same state bytes and digests, and the same canonically ordered
   action/refusal/successor row for every interior state, with no missing or
   extra state or edge;
8. derives a predecessor for every noninitial state at its recomputed minimum
   depth and rejects any state with no such witness;
9. recomputes minimum depths, convergence cells, and the closure digest.

The checker may call a world's native verifier and canonicalizer.  It may not
import the builder, a controller, a search policy, or an adapter method that
filters legal actions.  This avoids duplicating story and diagram semantics
while still catching a builder that hides inconvenient moves.

All generic code is forbidden from branching on a story, diagram, or future
world name.  A registry may select an implementation by declared adapter id;
the closure algorithm and checker remain the same.

## 6. Composition becomes an audit, not another edge

When two different action sequences reach one canonical state, the closure
may retain one bounded, deterministic pair.  It never enumerates all paths.
For every noninitial state, the checker derives the **primary predecessor** as
the lexicographically first `(predecessor_digest, canonical_action)` edge among
edges that establish the state's minimum depth.  Following primary
predecessors gives its canonical shortest route.

The checker then considers every other accepted incoming edge whose
predecessor's minimum depth plus one is within the horizon.  Ordered by the
same pair, the first edge whose reconstructed route differs from the primary
route is the one alternate.  The checker emits exactly one `ConvergenceCell`
for that end state, or none if no alternate exists:

```text
ConvergenceCell {
  start_state_digest  # always the registered initial state in the first slice
  primary_route[]
  alternate_route[]
  end_state_digest
}
```

There are therefore at most `number_of_states - 1` cells.  The
preregistration also freezes an **8 MiB maximum serialized closure size per
world**, including cells.  The checker derives the exact cell set and canonical
order from the graph; the builder cannot omit, inject, or cherry-pick cells.

Equal state keys with unequal canonical bytes are an architecture failure,
not a near match.  Two routes that end in equal bytes demonstrate only that
the registered operations commute on that case.  They do not establish that
the routes have the same informal meaning.

The formula matcher may become a later world only after its equality,
specialization, and piece-selection operations emit complete replay witnesses.
No prose-inferred bridge and no newly authored pairwise relation qualifies.

## 7. The first demonstration

Before a person supplies a target:

1. freeze one existing source snapshot per eligible world;
2. freeze each action schema, adapter digest, horizon, and resource ceiling;
3. build both closures with canonical breadth-first enumeration;
4. check and commit the closures and their manifests.

Only then does a person provide one exact endpoint per world.  The same query
command returns either a shortest replayable sequence or the bounded negative
answer.  The display names the snapshot, horizon, visited-state count, closure
digest, and native verifier.  It never converts a bounded negative into
unqualified prose.

Human-selected endpoints are a demonstration, not scored evidence.  Because
the closure predates them, they cannot steer construction; because they are
not scored, a maintainer cannot turn an impressive choice into a benchmark.

## 8. Construction gate registered before implementation

The preregistration commit must contain the schemas for `BoundedClosure`,
world registration, and result receipts; the generic checker skeleton; the
complete corruption generator; the two frozen source snapshots and manifests;
the exact horizons and resource ceilings; and tests that fail before the
builder exists.

Use canonical-LF SHA-256 for source manifests.  Generated source data remains
seed-derived and byte-identical.  No existing scored holdout is reused as
fresh evidence.

The first slice fires only if all clauses fire:

- **B1 — two real worlds register.** Exactly two already-committed worlds
  satisfy the four-operation contract without adding a new demonstration
  world.
- **B2 — blind closure finishes.** Canonical breadth-first enumeration closes
  each world at its frozen horizon with at most **512 distinct states**, at
  most **32 syntactic actions per interior state**, and at most **30 seconds**
  per closure on the registered release host; each canonical closure is at
  most **8 MiB**.
- **B3 — checking is complete.** The checker independently accounts for every
  schema action at every interior state; derives the exact reachable state,
  edge, refusal, predecessor, and convergence-cell sets; rejects all extras;
  and reproduces every returned witness.
- **B4 — corruption is always caught.** For each closure, the checker rejects
  every registered mutation class in section 9 across five fixed mutation
  seeds, with zero false rejection of the untouched control.
- **B5 — the abstraction is shared.** Generic builder and checker contain no
  world-name conditional and produce byte-identical output on a repeated run.
- **B6 — composition is exercised.** The closures naturally contain at least
  four convergence cells in total.  If the existing worlds form only trees,
  report that fact; do not author redundant actions to meet the count.

B1, B2, or B6 may honestly report `INSUFFICIENT_STRUCTURE`.  That is a miss,
not permission to resize the bound, add a toy world, or tune the snapshots.
There is no learned prediction in this slice and therefore no multi-seed
model comparison.

## 9. The corruption battery

The frozen generator makes each of these changes separately:

1. delete one legal action row;
2. make the untrusted builder conceal one known schema action;
3. change one successor while retaining its action;
4. mark one native refusal as a legal successor;
5. remove one reachable interior state;
6. alter the source digest, adapter digest, or horizon;
7. claim closure while omitting an interior frontier;
8. change a state's lookup key without changing its canonical bytes;
9. inject one well-formed but unreachable state and its self-consistent rows;
10. keep one route to a convergence state and corrupt the other;
11. omit, inject, or replace the canonical alternate convergence route;
12. reorder closure table rows or JSON object keys without changing their
    meaning.

Mutations 1–11 must be rejected with a named first disagreement.  Mutation 12
must normalize to the same bytes and closure digest.  Ordered semantic lists,
including action sequences, are never shuffled by mutation 12.  A check that
merely rehashes the builder's claims is vacuous; every load-bearing field is
recomputed from frozen sources and native verification.

## 10. Stop conditions and non-claims

Stop and park if either world is nondeterministic, its action domain cannot be
enumerated without executable callbacks, breadth-first enumeration exceeds a
frozen ceiling, any corruption passes, or the generic layer needs a
world-specific exception.

Do not:

- add a model to make exhaustive construction look like an AI result;
- call a timeout or horizon boundary a negative answer;
- select targets before the closure is sealed;
- hand-edit a closure or generated source;
- author a third world, duplicate action, or special case to satisfy a gate;
- claim the native verifier captures real-world truth;
- infer shared meaning from two equal endpoint states.

If the first slice fires, the next question is not “which model should rank
the actions?”  It is whether the same sealed closure can serve genuinely new
queries without regeneration, and whether witnessed formula operations can
join the interface without weakening the trust boundary.

## 11. How this lands

This document changes direction, not status.  No implementation result belongs
in `experiments/ANALYSIS.md` or `docs/DISCOVERIES.md` yet.  When the
preregistration lands, its live status must enter the then-current roadmap.
When construction is attempted, fires, misses, insufficient structure, and
resource refusals land together in the roadmap, analysis, discoveries, and
backlog.

The intended broader claim is deliberately stronger than another successful
demo and narrower than general planning:

> A small exact world can be compiled once, checked independently, and used
> later to give replayable positive answers and honest bounded negative ones.

That is the next bound worth pushing.
